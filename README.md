# BySide 咫尺

> 让相隔千里的家人，聚到同一张桌上。

异地家庭大多靠电话和视频维系感情。看见彼此当然是一种陪伴，但屏幕能给的只有"看见"——
你没法陪对方消磨一段时间，没法参与他此刻正在做的事，也没法一起完成点什么。

**BySide 想做的是屏幕之外的另一种可能：一起"在场"的感觉。**

两张相隔千里的桌子，各自架一台摄像头和一台投影仪。你在自己桌上移动一枚真实的棋子，
摄像头把它识别成坐标，对面的投影就在**完全相同的位置**把它还原出来。
反过来也一样。连上之后，两张桌面变成同一个空间。

被传递的是**位置**，不是画面。

📽️ **产品介绍页 → https://doris112233.github.io/byside/**

## 为什么不是又一块屏幕

我们没有再造一块屏幕，而是让"一起做事"这件事重新发生在真实的桌子上：
真的棋子、真的笔、真的毛线，用手去碰、去移动、去完成。
虚拟的部分只负责一件事——把这份真实，原样递到另一张桌子上。

> 陪伴不只是说话，更是一起做事，一起玩耍。

市面上的产品大多要么是纯屏幕，要么是纯实体、够不到远方的人。
半实体半虚拟这条路很少有人走，因为它意味着真的要做硬件、真的要做识别、真的要做投影，
而不是再开发一个 App。

## 这个仓库里是什么

**下棋，是我们第一个做实的场景**，用来验证"一起做事"这个核心机制真的成立。

所以这个仓库里是一套**可以真跑起来的双端实体五子棋**：摄像头识别桌面上的实体棋子，
投影仪把棋盘和对方的棋子打回桌面，两端通过坐标同步对弈。

绘画、手工、桌游、一起吃饭这些是同一套理念的延伸，属于产品方向，
**代码还没有**——介绍页上写的是我们想做的事，这个仓库里是已经做成的那一件。

零依赖：没有框架、没有构建步骤、没有第三方库。

## 运行

```bash
node server.js
```

- 本机：`http://localhost:8778/?seat=black`
- 另一台机器（同局域网）：`https://<本机IP>:8443/?seat=white`

摄像头在非 localhost 下必须走 HTTPS，所以需要自签证书。仓库里不含证书（私钥不进仓库），自己生成：

```bash
openssl req -x509 -newkey rsa:2048 -nodes -days 3650 -keyout key.pem -out cert.pem -subj "/CN=localhost"
```

浏览器会警告自签证书，选「高级 → 继续前往」。

## 两种跑法：电脑版 / 板子版

**同一份代码，两个启动脚本。** 网页、中继、识别算法、网络层全是一份；
不同的只有三处：摄像头从哪来、浏览器跑在哪、怎么启动。所以**开发不分 branch**——
分了以后每个修改都得做两遍，两边迟早会不一样。

仓库里有一个 `rdk` 分支，但它不是开发线，是「在板子上实测通过的稳定版」：
日常改动都进 `main`；每次在 RDK 上跑通一轮，就把 `rdk` fast-forward 到那个提交
（`git push origin main:rdk`）。板子上克隆的是 `rdk` 分支，不会被 `main` 上还没在板子验过的改动影响。

每一端都是三样东西：

| | 做什么 | 电脑版 | 板子版（RDK X5） |
|---|---|---|---|
| 桌面界面 | 投影到桌上的网页，遥控器操作 | 笔记本上的浏览器，拖到投影仪那块屏上全屏 | 板子上的浏览器，开机自动全屏 |
| 识别 | 朝下看桌子的摄像头 → 棋子坐标 | `rdk/app.py --headless`（同一个程序） | 同左，systemd 服务 |
| 中继 | 两端之间传坐标、邀请、签声网 token | 本机 `node server.js`，或云上的 | 云上的，或板子本地 |

### 电脑版

```bash
scripts/pc.sh --name 奶奶                          # 第一次会自动生成好友码
scripts/pc.sh --camera http://手机IP:8081/video    # 用手机当朝下的摄像头
scripts/pc.sh --server wss://你的域名/ws           # 连云上的中继
```

笔记本**自带的摄像头朝着人脸，留给视频通话**；识别要另一个**朝下看桌子**的
（影石 Insta360、USB 摄像头或手机）。Mac 上 `--camera auto` 按名字找影石，不带就默认 1 号（第一个外接的）。
第一次跑 macOS 会问「终端要用摄像头」，要点允许，不然 OpenCV 打不开任何摄像头。

键盘的方向键 + 回车 + Esc 就是遥控器。

#### 两台电脑、两台投影仪，同一个 Wi-Fi

1. **甲**（起中继的那台）：先生成一次自签证书（见上面那行 openssl），然后
   `scripts/pc.sh --name 甲 --camera auto`。终端最后会打印乙要用的命令。
2. **乙**：`scripts/pc.sh --name 乙 --camera auto --server ws://甲的IP:8778/ws`。
   乙的识别端走明文 ws；乙的浏览器会自动改走 `https://甲的IP:8443/app/`
   （不是 localhost 的页面必须 HTTPS 才给开摄像头和声网），Chrome 以忽略自签证书的方式打开。
3. 两边各把弹出的窗口拖到投影仪那块屏，⌃⌘F 全屏。
4. 标定：手机打开各自的 `http://那台电脑IP:8080/`，点「显示标定图」——桌上出现方框和四个 ArUco 标记，
   摄像头认出它们后标定页上的四个角会**自动跳到位**（状态栏显示「看到 4/4 个标记 ✓」），
   点「开始游戏」即保存。认不出（标记被遮、太暗）就还是手动拖四个角。投影窗口里按 `C` 也能开关标定图。
5. 甲乙互加好友码，一方点对方头像 → 下棋 → 对方点「好呀」。桌上放真棋子，对面亮环。

### 板子版

板子上拿 `rdk` 分支（稳定版），跑一次，之后插电开机全自动：

```bash
git clone -b rdk https://github.com/Doris112233/byside && cd byside
scripts/rdk-setup.sh --name 奶奶 --server wss://你的域名/ws
scripts/rdk-setup.sh --name 奶奶 --local-relay      # 局域网自测
```

⚠️ 板子上自动开浏览器这一步**还没在 RDK 上实测过**——Ubuntu 22.04 的
Chromium/Firefox 是 snap 包，能不能跑、带不带得动视频通话要开机验证。
另外板子如果只有一个摄像头，它被桌面识别占着，视频通话会退成只有声音。

### 云服务器（跨城必需）

两个人在不同城市，中继得放在两边都连得上的地方，而且要 HTTPS（摄像头和声网都要求）。

推荐**腾讯云轻量 · 香港 · 锐驰型**（约 40 元/月）：香港不用备案、当天能用，到大陆延迟
30–50ms，支付宝付款。别选入门型——腾讯云写明它不保证到大陆的跨境网络质量。
域名在同一个后台买个 .com，做实名认证（当天通过，和备案不是一回事）。

买好之后，控制台里先做两件事：域名 A 记录指到服务器 IP；防火墙放行 80 和 443。然后：

```bash
curl -fsSL https://raw.githubusercontent.com/Doris112233/byside/main/scripts/server-setup.sh -o setup.sh
sudo bash setup.sh --domain byside.你的域名.com
```

装 node + Caddy（自动申请续期 HTTPS 证书，天然支持 WebSocket），问你要声网证书
（只存在服务器上）。之后 `https://你的域名/app/` 就是桌面界面，两边都连它。

### 声网

项目开了 App 证书，所以音视频要 token。**证书只放在跑中继的那台机器上**：

```bash
cat > agora.env <<EOF
AGORA_APP_ID=你的AppID
AGORA_APP_CERT=你的证书
EOF
chmod 600 agora.env        # 已在 .gitignore 里，不会进仓库
```

网页进了会话会问中继要 token，中继只给确实在这个会话里的人签
（签法已和声网官方 `agora-token` 包逐字节比对过）。右下角那枚小标会写明当前走的是「声网」还是「原生」。
没配证书时作为备用退回浏览器原生 WebRTC —— 只有 STUN 没有 TURN，跨城对称 NAT 下大概率连不上，正式用一律声网。

**通话传的是桌面，不是人像**：现在每端只有一只朝下拍桌子的摄像头（人像留作以后第二只摄像头的选项）。
识别端在跑时（首页显示「桌子已连上」），网页从识别端的 `http://localhost:8080/stream.mjpg` 取画面当视频轨发出去，
因为同一只摄像头两个程序开不了；识别端没跑才直接开摄像头，名字像 Insta360 / 影石 / Link 的优先。
要指定摄像头就打开一次 `?cam=名字片段`（比如没接影石时 `?cam=FaceTime`，会记住）；识别端不在本机用 `?desk=http://主机:8080`。
一边声网连不上退回原生时会通知对方一起退，不会出现一边在声网频道、一边在等原生 offer 的情况。

## 现场流程

1. 两端分别打开 `?seat=black` 和 `?seat=white`，各选自己的摄像头
2. **开启 ROI → 调整框选**：把四个角拖到实体棋盘的四个角
   （四角可各自摆放，投影歪成梯形也能贴合）
3. **投影模式**：打开纯输出窗口，拖到投影仪那块屏，按 `F` 全屏
4. 需要的话用**梯形校正**把投出来的棋盘调正
5. 往桌上放实体棋子即可，识别到就自动同步给对方

参数按座位存进 localStorage，刷新自动恢复。

## 实现要点

| 模块 | 说明 |
|---|---|
| 坐标映射 | 屏幕上格线画在哪，就反解到摄像头画面的对应位置取样（所见即所测），无需第二套标定 |
| 自动标定 | 投影仪在棋盘里离四角 1.5 格处打出 4 个 ArUco（网页与 `rdk/calib_aruco.py` 同一套图案），摄像头认出中心后用单应外推回四个角；投影仪和摄像头用的是同一个参照物 |
| ROI | 任意四边形，通过单应变换映射到屏幕棋盘方框 |
| 棋子识别 | 免基准：内圆中位数 vs 外环中位数。两者都用中位数以抵消穿过交叉点的格线。另备 `--detector onnx --model best.onnx` 走 YOLO 模型（`rdk/detect_onnx.py`，采数据→标注→训练→导出的步骤写在文件头），框中心落到最近格点，接口与 classic 一致 |
| 抗干扰 | 充满度判据挡掉高光小斑；每端只认自己那一色，白端因此不受阴影影响 |
| 遮挡保护 | 变化点数超标时看图样是否稳定——手会动，棋子不会 |
| 梯形校正 | 四角可调的单应变换，同时作用于视频（CSS matrix3d）和棋盘（绘制坐标），两者严格对齐 |
| 同步 | WebSocket 中继跨机器，同源时回退 BroadcastChannel |
| 投影输出 | 独立窗口被动渲染，控制窗常驻广播状态 |
| 通话叠加 | 对方画面左下角一枚「在玩什么 / 该谁了」小标（两边各自从本地状态推）；互动表情走中继快通路，不进日志不重放 |

仓库里还保留着一套自写的 ArUco 检测器（自适应二值化 → 连通域 → 凸包 → 内接最大四边形 → 局部 Otsu 解码），
早期用标记定位棋盘时写的，现在默认不启用，可在面板切回。

```

index.html            旧版单页：浏览器里识别 + 投影的实体五子棋，仍可独立运行

```
